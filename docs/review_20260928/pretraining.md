## Conclusion

The scientific aim is credible: infer a source-exclusive retained decay forest from detector observations, using hierarchical representation learning and level-wise mother/daughter assembly. The contracts correctly separate detector observations from MC targets, preserve daughter-sum four-momentum, and restrict evaluation claims. The studies do **not** yet demonstrate reliable deep hierarchy reconstruction, a benefit from hyperbolic pretraining over a Euclidean or unpretrained control, or a controlled data-size effect.

Holding 70,000 training events and completing the already registered independent Phase62 replication is defensible. Continuing a long sequence of parent/PID scalar-weight doses would be weak experimental design. The next priority should be correcting representation diagnostics and identifying the failure mechanism: radial saturation, coarse pretraining supervision, teacher-composite distribution shift, or downstream assembly. These are hypotheses to distinguish experimentally, not established explanations for the poor strict results.

Phase61's completed refinement is execution evidence. Its aggregate relation accuracy 0.839654, parent-ranking statistic 0.729542, and PID accuracy 0.884295 coexist with 27/3,412 retained full LCAG pairs and zero coherent primary forests. Those pretraining statistics cannot be interpreted as deployment-quality hierarchy measures. The parent statistic additionally averages an unsupported FSP view into its denominator, and channel retrieval reuses the same physical branch across views; both need reporting repair before being used to select a scientific representation. Evidence: `docs/wiki/phase61.rst:4`, `:42`, `:50`, `:66`, `:513`.

## Ranked findings

### P1 — Cross-event channel retrieval is contaminated by repeated views of the same branch

`_validate_pretraining` appends branch embeddings and channel labels on **every** named curriculum view (`src/hypertagging/training/pretrain_trainer.py:2094`). Two views are both `TRUTH_GUIDED_MULTILEVEL` (`training/pretraining_curriculum.py:42` and `:49`), so these can contain identical representations of the same physical branch. Retrieval concatenates all these embeddings, masks only the diagonal, and counts any matching channel ID as a peer (`training/pretrain_trainer.py:2115`). It has no event/branch-identity exclusion. A branch can therefore retrieve itself under another view; even a singleton real channel acquires an artificial positive peer.

This does not leak truth into production inference, but it invalidates an interpretation of the metric as independent cross-event channel generalization. It can also affect the diagnostic `best_channel_retrieval.pt` track. Phase61 records 1,176 retrieval queries and approximately 0.667 retrieval accuracy; do not present these as independent branch retrieval efficiency.

**Update:** serialize event UID, branch identity, view and source group alongside validation embeddings. Report each view separately. Exclude the same physical branch from all candidates, and report cross-event and cross-source retrieval separately with true peer-availability counts. Preserve old metric keys as historical diagnostics and version the corrected metric; do not rewrite past receipts. Add a meaningful fixture in which every real branch has a unique channel and repeated views must yield zero eligible retrieval queries.

### P1 — Apparent non-collapse does not establish a usable radial hierarchy; native logs strongly suggest saturation

The actual Phase61 refinement has `max_tangent_norm=1.5`, `radius_depth_weight=0.02` and generation-height radius targets. Tangent bounding is `M*tanh(norm/M)` (`models/hyperbolic.py:81`); at curvature one, the maximum hyperbolic radius is approximately 3. The target radius is 0.1–1.5 (`losses/hyperbolic_pretraining.py:472`). Native control FSP losses at steps 1 and 547 are 2.25000048 and 2.24999976—consistent with every leaf sitting near radius 3 instead of its target 1.5. The final control raw shared-encoder gradient norm for radius is `1.018675e-6` versus `0.520186` for LCA; after its 0.02 weight, radius contributes only `2.03735e-8`. Validation radius loss stays approximately `2.7762244` between steps 1094 and 2188, with radius/level correlation only `0.00413` at the end. The candidate shows the same pattern in the extracted evidence.

The logged zero `boundary_fraction` is insufficient to dismiss this: it checks Poincaré coordinate norm >=0.95 (`losses/hyperbolic_pretraining.py:1015`), whereas the tangent cap maps to `tanh(1.5)≈0.905`. A representation can be fully saturated at the model's own cap while passing that boundary diagnostic. Effective rank near 24 can reflect angular spread with almost no radial variation.

**Evidence status:** observed losses/gradient imbalance are measured native evidence; cap saturation is a strong mechanistic inference, not a directly measured pre-cap activation result. Confirm it by a bounded read-only CPU forward on a fixed existing development cohort, recording pre-cap norm, derivative `sech²(norm/M)`, post-cap radius quantiles, and per-level radial variance. Inspect both the historical initialization and refined checkpoints. Do not increase the radius weight blindly. If saturation is confirmed, compare a scale-reconditioned projection or a trainable bounded radial parameterization against the unchanged baseline, retaining angular information and all data/budget controls. A meaningful success condition is non-negligible radial gradients plus better depth-stratified strict topology, not merely a lower radius loss.

### P1 — The current parent objective cannot learn the fine parent discrimination claimed by its name

The parent loss ranks the true parent against nodes in different B branches, falling back to unrelated/unknown nodes. It explicitly excludes same-immediate-mother, same-local-branch, and same-B relations (`losses/hyperbolic_pretraining.py:118`, `:156`). Its score is symmetric hyperbolic distance; direction comes only from choosing parent-labelled positive pairs. Consequently it does not train the distinction between the actual parent and a plausible wrong mother inside the same branch, which is the difficult assembly decision. Increasing its scalar weight from 1 to 2 tests coarse family separation more directly than immediate-parent selection.

The reported overall parent statistic further includes an FSP-only view without eligible visible parents, whose ranking function returns zero (`losses/hyperbolic_pretraining.py:429`; `training/pretrain_trainer.py:2067`), then averages all view/batch values (`:2130`). With one unsupported view out of four its aggregate ceiling is about 0.75. Thus 0.7295 is compatible with approximately 0.973 on supported views; it is not 72.95% fine-grained parent reconstruction accuracy. Exact supported micro rates require reaggregation of counts and masks, not division of the historical rounded statistic.

**Update:** retain this loss as a coarse-separation auxiliary, but name it accordingly. Add a distinct ordered edge classifier or listwise parent objective using child/candidate projections, valid level direction, and explicit non-parent negatives from the same branch. Never turn all nearby/ancestral nodes into generic repulsive metric negatives, which would conflict with tree-distance geometry. Test its exact-parent top-1/MRR and same-branch sibling confusion separately from coarse family accuracy. Report each view's numerator/eligible denominator, with unavailable values for unsupported views.

### P2 — The gradient guard catches dominance relative to LCA, not useful multi-objective learning

The guard compares the largest weighted principal gradient against LCA's weighted gradient (`training/pretrain_trainer.py:2607`). If LCA shrinks because it is learned, the ratio can fail without numerical divergence; conversely an almost ineffective radius gradient passes as long as it is nonzero (`:2596`). This explains what the Phase56/58/60 failures mean operationally: they triggered a preregistered balance guard. It does not prove that the mathematical objective diverged or that an optimizer step would have corrupted training.

**Update:** preserve the existing guard for already registered studies. Add diagnostic-only rolling per-objective gradient magnitudes, update-to-parameter ratios, cosine conflicts, support fractions, and pre-cap saturation. Use these to preregister a single new balancing experiment if justified—for example charge-compatible PID cross-entropy or split PID/geometry gradients—rather than repeatedly lowering a weight until one seed completes. Do not retrospectively relax a failed run's threshold.

### P2 — Pretraining validation aggregates mix populations and its “full training objective” does not use the phase PID weights

Most validation losses, rates and even support counts are unweighted means over batches and named views (`training/pretrain_trainer.py:2038` through `:2133`). The last partial batch has the same weight as a full batch. `validation_full_training_objective` uses `config.leaf_pid_weight`, not `_leaf_pid_training_weight`, and always adds corruption/correctness/hard-negative terms even when the named phase does not train them (`:1990`). The current schedules vary `leaf_pid_phase_weights` while leaving `leaf_pid_weight=1`, so this is better understood as a fixed reference diagnostic objective, not the exact scheduled optimization objective. Phase61 documentation correctly warns that these are not global micro rates, but the name remains easy to misuse.

**Update:** publish loss numerator/support pairs and explicit reduction semantics, phase-specific actual weighted losses, a separately named fixed reference objective, per-class relation confusion, and macro-by-event/source/channel/depth views. Keep absent objectives unavailable rather than successful zeros. Use a preregistered fixed checkpoint or an independently defined downstream development metric for a representation comparison. Phase61's fixed final refinement checkpoint avoids directly promoting the flawed channel retrieval track; that is a sound existing control.

### P2 — Curriculum realism and charge support should be tested before adding more loss terms

The two-pass detector-PID → rebuilt kinematics → contextual encoder path is shared with reconstruction (`training/pretrain_trainer.py:295`) and is a useful design. Yet phases 2/3 train on truth-built composites, and phase 4 corrupts them using deterministic node-position modes, first/last daughters, and a cyclic token change (`training/pretraining_curriculum.py:297`). These may be easier or differently distributed than actual decoder errors. Corrupted invalidity correctly propagates upward and invalid candidates are removed from positive structural supervision (`:238`). This is a software strength, but no measured equivalence to free-rollout state distributions is established.

Raw-track PID cross-entropy uses every vocabulary logit (`training/pretrain_trainer.py:2706`), while runtime PID decisions mask to charge-compatible stable species (`reconstruction/pid_state.py:42`, `:151`). The trained and deployed categorical supports therefore differ. This is not an established bug or proven cause of dominance, but a precise low-complexity ablation is available.

**Update:** evaluate PID accuracy/confusion/NLL separately by charged species, momentum, detector-availability pattern and source category. Compare charge-masked loss with the current full-vocabulary loss at matched weights and budgets; fail on genuinely incompatible charge/target labels rather than silently hiding them. For candidate supervision, collect invalid candidates generated by an older checkpoint on training events only, with immutable identity, and compare these to existing synthetic corruptions. Preserve a separate development cohort and avoid feeding strict validation candidates back into training.

## Preprocessing, splits and normalization

The current v4 design is sound in principle: raw track p3/charge/PID likelihood and multiple mass-hypothesis energies are reconstructed inputs; MC PID stays a target; mother four-momentum is the recursive sum of daughters; shared ECL/KLM/copy sources have explicit provenance; missing detector values have masks. Track-fit choice is MC-independent and alternative policies are versioned (`docs/preprocessing_design.md:286`). Input daughter-PID histograms are distinct from truth histograms (`:360`). Do not revert these distinctions to make losses easier.

The highest scientific preprocessing question is **what can possibly be represented**. `complete_only` means completeness within the retained tree after missing leaves are dropped; it is not complete physical decay reconstruction, and `complete_only`/`reconstructable_partial` can coincide (`docs/preprocessing_design.md:367`). Before another training family, publish a truth-only representability census on a development cohort: all physical roots → detector-supported roots → retained ontology-compatible roots → arity/query-capacity-compatible roots → eligible targets. Stratify by charged-B, neutral-B, continuum, depth, multiplicity, missing charged/neutral particles, KLM status and pruning reason. Keep the all-event primary denominator and a clearly labelled attainable-subset diagnostic. This distinguishes a ceiling created by data/ontology from a model failure without hiding failures.

Scientific source-role manifests reject raw event-prefix shortcuts, validate exact identities, and exclude sealed test (`training/data_module.py:858`, `:1069`). Source groups cannot leak across splits (`:1244`). Train-only masked normalizers are appropriate (`:1336`, `:1404`); target-only composite metadata are excluded. Static track/ECL transforms and runtime common/composite transforms are separated (`:531`). Preserve zero-observation runtime identity scaling. Dataset expansion must not refit statistics with validation events.

**Updates to preprocessing QA:** report real per-feature coverage and masks, source overlap/reco duplication, signed charge/PDG agreement, physical reconstructed-minus-MC residuals on truth-matched eligible particles, and event/run/source distribution shifts. Exact daughter-sum closure is only an implementation invariant; it cannot substitute for momentum or mass resolution. No need to change the v4 JSON-in-Parquet format on scientific grounds before a representative storage benchmark. Track-fit-policy and KLM inclusion ablations should use matched sources/seeds/compute with acceptance and completeness denominators, not merely closure tests.

## Transfer and experiment design

Parameter-only warm-start validates all named tensor shapes/dtypes/finiteness and deliberately resets normalizer buffers, optimizer, schedule, RNG and channel memory (`training/pretrain_trainer.py:380`). This avoids stale optimizer/statistics contamination, but changes the function presented to the historical weights when normalization changes; measure activation/gradient distributions before assuming the warm start is a uniformly healthy representation.

Phase61 loads 121/121 encoder keys and both PID-head keys, freezes PID for reconstruction and adapts the encoder after reconstruction step 2188 (`docs/wiki/phase61.rst:513`). Coverage establishes transfer mechanics, not useful transfer. Current refinement comparisons have both arms refined and therefore do not isolate the value of refinement itself (`scripts/build_reconstruction_phase55_preregistration.py:49`). A minimal representation study needs a current-source no-refinement control; a later scientific baseline should compare contextual Euclidean and hyperbolic encoders at matched capacity/compute and data.

Configured seeds did not produce identical Phase61 pre-treatment parameters: 123/141 tensors differ at step 1094; first logged divergence is step 944 (`docs/wiki/phase61.rst:42`; external `phase61_review_20260927/shared-prefix-audit.json`). Do not describe the late-weight contrast as an exact common-prefix experiment. For a future paired treatment, train the shared prefix once and fork the entire checkpoint state—including optimizer, scaler, RNG, sampler/curriculum/memory and data-order identity—then apply only the intended treatment. Also repeat independent seeds; shared-prefix pairing reduces noise but is not a substitute for seed replication.

Recommended falsifiable sequence, following the already registered Phase62 closeout:

1. **No-training diagnostic repair:** corrected per-view/eligible micro metrics, event-excluded channel retrieval, pre-cap/radius gradient diagnostics, representability census and assembly failure stages. Decision: identify which bottleneck has a measurable deficit; no model promotion follows from metric repair alone.
2. **One representation-mechanism contrast:** choose either radial reconditioning if confirmed saturated, or same-branch ordered-edge supervision if radial learning is healthy. Fixed 70k data, identical budgets/normalizers/decoder/split, common-prefix checkpoint, and at least two independent seeds. Falsification: no joint gain in depth≥2 strict topology and nontrivial forest recovery despite an improved auxiliary diagnostic rejects the claimed transfer mechanism.
3. **One deployment-distribution contrast:** decoder-generated training composites versus current synthetic corruption, with evaluation on a fresh confirmation cohort. Falsification: lower corruption loss without improved free-rollout hierarchy means the auxiliary task remains a poor surrogate.
4. **Representation baseline / controlled data scaling:** once the training path is stable, compare current-source no-refinement, Euclidean and hyperbolic controls; then separate data-size from compute using an explicit size×budget design. Earlier Phase40 jointly changed size, steps and cohort, and Phase42 did not establish longer-pretraining benefit (`docs/wiki/phase61.rst:507`). These histories justify uncertainty, not a conclusion that data scaling cannot help.

Use already scored development cohorts for debugging and error taxonomy rather than consuming another fresh confirmation cohort for every exploratory diagnostic. Reserve untouched validation only for preregistered comparisons; sealed test remains separate. Event-level paired uncertainty is conditional on the selected models and does not measure seed variation. Where sources repeat across cohorts, add source-group sensitivity estimates before generalization claims.

## Evidence and limitations

`pretraining_native_evidence.json` in this directory contains source-log paths, SHA-256 values, native loss configuration and selected existing training/validation scalars for both Phase61 arms. It is a compact new extraction, not a replacement for historical receipts. The observed radial evidence is from the real completed run; scientific behavior has not been changed to “fix” those numbers. Historical study conclusions were checked against the current authoritative Phase61 synthesis and current status rather than treating old audits as current specifications. A fresh exhaustive rerun of all studies was neither needed nor performed.

The strongest immediate actions are metric correction and the bounded saturation diagnostic. Changes to loss weights, radius parameterization, ordered-parent supervision, corruption distribution or data policy should be introduced as new versioned studies with meaningful contract tests and preserved scientific denominators.
