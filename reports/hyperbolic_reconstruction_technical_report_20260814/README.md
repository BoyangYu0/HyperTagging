# Hyperbolic reconstruction technical report package

This directory contains the delivered portable HTML report, deterministic evidence snapshot, canonical report artifact, and builder audit receipt for the technical report dated 2026-08-14. `report.html` is the primary reader-facing surface.

The artifact status is `partial`. Repository data/publication evidence, CPU-tested model construction, capacity metadata, and bounded diagnostic execution are available. Long GPU convergence, free-rollout scientific quality, category/channel robustness, calibration, and sealed-test results are absent. Three serialized scientific-submission blockers remain active, and the physical-relation-only named ablation arm is not yet present.

## Package contents

- `.gitattributes`: preserves the verbatim builder receipt as non-text audit data without line-ending normalization.
- `generate_evidence.py`: allowlisted deterministic extractor, CPU model counter, and canonical artifact builder.
- `evidence.json`: fixed-date observed/planned/unknown evidence layer with 18 bounded datasets.
- `artifact.json`: canonical `surface: report` manifest/snapshot/source payload with 11 visible sections, 11 charts, 6 tables, and partial-status access issues.
- `report.html`: primary self-contained portable report with semantic fallback, embedded canonical payload, inline chart representations, and no external asset dependency.
- `delivery_receipt.json`: verbatim portable-builder audit receipt.
- `source_notes.md`: evidence spine, grain, claim map, section map, assumptions, omissions, caveats, and reproducibility boundary.
- `chart_map.md`: analytical question, chart selection, fields, claim, palette semantics, and source for every chart.
- `tests/test_report_evidence.py`: deterministic generation, evidence-boundary, and canonical artifact contract tests.

No GPU, scheduler, job, checkpoint, or sealed-test access is required or permitted for regeneration or report review.

## Portable delivery and QA status

The official portable builder returned `ok=true`, with `validation=passed`, `package=passed`, and `verification=structural_only`. Its receipt records 31 blocks, 11 charts, 6 tables, no custom HTML blocks, and no metric cards; those counts match the embedded canonical artifact. Local structural review also confirmed that `report.html` is non-empty, contains the exact report title, embeds unchanged canonical `surface`/`manifest`/`snapshot`/`sources` data inside a read-only portable envelope, and declares no external resource dependency.

`structural_only` is a real QA limitation. No compatible Chromium headless-shell was available on the packaging host, so enhanced-reader browser behavior, responsive viewport behavior, source-dialog behavior, and source interaction were not exercised. The semantic fallback remains present, but this receipt is not browser certification.

`delivery_receipt.json` is retained verbatim. Its `html` field is an absolute Windows path from the local QA packaging host. That field is isolated builder metadata: it is not a canonical report path, artifact source path, or provenance record, and must not be normalized into `artifact.json`.

## Regenerate evidence and artifact

Run from the repository root:

```bash
/home/b/Boyang.Yu/.local/bin/uv run python \
  reports/hyperbolic_reconstruction_technical_report_20260814/generate_evidence.py \
  --repo-root /home/b/Boyang.Yu/HyperTagging_uni/HyperTagging
```

The command rewrites `evidence.json` and `artifact.json` with fixed `generatedAt=2026-08-14T00:00:00Z`. It fails on missing required inputs, unsafe metadata-root overrides, cross-source disagreement, or changed safety/readiness contracts.

To relocate a permitted logical metadata root inside the repository, repeat `--metadata-root KEY=PATH`, where `KEY` is one of `artifacts`, `configs`, `docs`, or `src`. This changes location only; it does not expand the exact-file allowlist.

## Portable report regeneration boundary

`generate_evidence.py` deterministically regenerates `evidence.json` and `artifact.json`; it does not overwrite the delivered `report.html` or verbatim `delivery_receipt.json`. Any future portable rebuild must use the official builder against the checked canonical artifact, preserve a new receipt exactly, and repeat structural plus browser QA when a compatible browser is available. Rebuilding the report never authorizes sealed-test inspection, submission, or GPU execution.
